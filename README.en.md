## <img src="./profile-assets/v3/chip-06-workflow.svg" height="28" align="absmiddle" alt="06 ~/workflow" /> How I build software

<img src="./images/mahiro-v2/mahiro-debugging.webp" align="right" width="29%" alt="Mahiro debugging code and resolving an alert in a workflow" />

I treat every project as an engineering cycle: **understand before building, validate before deploying and document to keep improving.**

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="./profile-assets/v3/workflow-en-dark.svg" />
  <source media="(prefers-color-scheme: light)" srcset="./profile-assets/v3/workflow-en-light.svg" />
  <img src="./profile-assets/v3/workflow-en-light.svg" width="440" alt="Development workflow: 1 Understand, 2 Design, 3 Build, 4 Validate, 5 Deploy, 6 Improve" />
</picture>

<br clear="all" />

<details>
<summary><strong>View each stage in detail</strong></summary>

<br/>

1. **UNDERSTAND** — Understand the real problem and workflow before implementation.
2. **DESIGN** — Prefer a simple, maintainable and verifiable solution.
3. **BUILD** — Implement incrementally with clear boundaries.
4. **VALIDATE** — Test behavior, data integrity and regressions.
5. **DEPLOY** — Protect the separation between development and production.
6. **IMPROVE** — Document decisions and keep evolving the product.

</details>
